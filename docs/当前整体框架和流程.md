## 二、skill-engine 是什么

一个**独立的 LLM Agent skill 解析、路由与执行引擎**：兼容 Claude Code Agent Skills 开放标准核心子集，不依赖任何 AI 产品，自带 CLI 与 Web UI。

**核心契约：**
- Skill = 一个文件夹，含 `SKILL.md`（YAML frontmatter + Markdown 正文）
- 标准字段：`name` / `description` / `when_to_use` / `arguments` / `groups`
- 引擎扩展字段（CC 静默忽略）：`human_in_loop` / `turn_policy` / `extra_tools` / `context_budget` / `mcp_servers` / `strict_file_tracking` / `verify_command` / `verify_timeout` / `compact_tool_output` / `compress_template` / `confirm_edits`
- 正文可选 `## Steps` DSL；调用方可按名字直连 `run <name>`（不经路由）

**定位纪律**：通用能力沉引擎核心，领域专用能力留 skill 层（code-builder 的 `cb_ast_map`/`cb_git_checkpoint` 在它自己的 tools.py）。新能力落地前必答："非 coding skill 会怎样"——答案只能是"无感知"或"可选启用"。

## 三、核心流程

### 3.1 发现 / 注册 / 路由（V0.3，未变）

```
discovery 扫描 **/SKILL.md → SkillMeta 索引
registry 三层 meta 合并：SKILL.md < .skill-meta.yaml(LLM 抽) < .skill-local.yaml(用户覆写)
router 三步：精确(name/alias/shortcut) → 关键词打分(jieba+intention) → LLM 兜底
→ MatchPlan(single/multi)
```

> 详细设计见 `skill路由优化方案.md`。

### 3.2 执行（Runner 四路分流）

| 档位 | 机制 | 适用 |
|---|---|---|
| 档位 A | 单次 LLM 调用 | 生成类 skill |
| Steps DSL | 确定性步骤（llm/exec/read/write） | 流程固定 skill |
| **档位 B（tool_dispatch）** | **LLM 工具循环 + P0 编码基建** | 编码/文件操作类 |
| pipe | 只返回编译后 prompt | 管道外部工具 |

**档位 B 循环要点**（V0.4 增强后）：
- 工具集 = 内建 9 个（bash/read/write/edit/search/restore/web_search/time/stop）+ `restore_file` + skill extra_tools + MCP 工具（session 模式另注入 `ask_user`）
- **FileStateTracker**：edit 前校验"已读且未变"（软/硬约束由 `strict_file_tracking` 决定）；bash 执行后保守失效
- **三级上下文压缩**：L1 折叠旧的大块工具输出 → L2 任务中立结构化摘要（可 `compress_template` 覆盖）→ L3 截断兜底；token 估算对中文修正；预算默认 32768（`SKILLS_ENGINE_CONTEXT_BUDGET` 可配）
- **search_files**：ripgrep 优先（含 `--no-require-git`，尊重 .gitignore），无 rg 回退纯 Python；`max_results` 参数化
- **verify_command 钩子**：轮内有写盘后自动执行声明的验证命令，失败提取 FAILED/ERROR 清单结构化回灌
- **diff 预览门**：`confirm_edits: true/batch`，写盘前 unified diff + 用户确认（difflib 零依赖）
- **bash timeout**：LLM 可按需传参，引擎钳制硬上限 600s
- **FileSnapshot**：写前自动记录原内容，`restore_file` 一键回滚

### 3.3 多轮会话（Session/REPL，V0.4 新增）

```
skill-engine session "任务" --skill code-builder -w <项目目录> [--resume-from <state>]
```

两层解耦：`run_repl`（外层编排）持有 `SkillSession`（messages + FileSnapshot + FileStateTracker + state_path），循环驱动唯一执行内核 `run(session_mode=True)`；内层无 tool_calls 时以 `stopped_by="session_turn_end"` 交还控制权。每轮落盘，Ctrl+C 不丢，`--resume-from` 续接。详见 `多轮会话模式-session-repl设计.md`。

### 3.4 创建（Creator + Designer，Phase 11，未变）

`skill-engine create "意图"` → Designer(LLM 出 JSON 设计) → Creator(机械渲染) → Validator(编译验证)。详见 `phase11-llm-native-design.md`。

### 3.5 安全审批（V0.4 增强）

- 三档模式：strict（LLM 侧 bash 直接 BLOCK）/ permissive（命令级检查）/ off
- 会话级审批缓存：y(本次)/Y(会话允许)/N(拒绝)/r(会话拒绝)/A(全部允许)
- 文件安全门：RISKY_FILENAMES + 路径出界检查
- V0.4 新增：FileStateTracker 一致性门、confirm_edits 确认门、快照回滚兜底
- 已知边界：working_root 非权限边界（绝对路径透传）；无沙箱。P1 计划可写根集合 containment

### 3.6 MCP 外部工具（V0.4 新增）

`mcp.json` 声明 servers（stdio/HTTP/SSE），skill frontmatter `mcp_servers: [name]` 引用；工具并入 bind_tools（同名时内建优先）。

### 3.7 命令行（主要命令）

| 命令 | 作用 |
|---|---|
| `list` / `info` / `match` / `scan` | 路由与查询 |
| `run <name>` | 按名执行（`--llm` / `--steps` / `--tool-dispatch` / `--state-path` / `--resume-from`） |
| **`session`** | **多轮持续会话（V0.4）**：`-s` 指定 skill，`-w` 工作目录，`--resume-from` 续接 |
| `index` | Preprocessor 抽取 `.skill-meta.yaml`（`--rebuild-meta` 全量） |
| `create` | LLM 原生创建 skill |
| `install/uninstall/update` | skill 安装管理 |
| `scan-security` / `web` | 安全扫描 / Gradio UI |

## 五、与 code-tutor-agent 的接入（CTA Skills 套件，未变）

三个 CTA skill（`cta-generate-problem/solution/test-cases`）经 editable 安装接入；双通道：adapter（进程内主通道）/ cli（逃生舱）；出题四级降级链 LLM → adapter → cli → 静态题库。产物经 `parse_problem_markdown` 解析为标准分节。详见 V0.3 文档第五章（内容仍准确）。

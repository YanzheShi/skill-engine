## 二、skill-engine 是什么

一个 CLI 优先的 **LLM Agent skill 引擎**，让 LLM 通过调用「插件式 skill」完成具体任务。

**核心契约：**
- Skill = 一个文件夹，含 `SKILL.md`（YAML frontmatter + Markdown 正文）
- frontmatter 字段：`name` / `description` / `when_to_use` / `arguments` / `groups`，可选引擎扩展 `alias` / `shortcuts` / `intent_verbs`
- 正文可选 `## Steps` DSL（`type: llm / exec / read / write`），`exec` 跑 `python scripts/xxx.py`
- 调用方（如 code-tutor-agent）可**按名字**直接 `run <name>`（不经自由文本路由）

**设计哲学**（来自 Phase 11 铁律）：
- LLM 驱动，非脚手架工具：`create "自然语言意图"` → LLM 设计 → Creator 落地
- 架构分离：Designer（LLM 层）/ Creator（纯机械渲染）/ Validator（验证）
- CLI 不暴露内部结构

## 三、核心流程

### 3.1 发现（Discovery）

```python
from skill_engine.routing.discovery import discover
discovery = discover(roots=[...])   # 默认只扫项目目录，快速
```

- 扫描 `**/SKILL.md` → 解析 frontmatter → `SkillMeta`（轻量）
- 注册到 `Registry.index`（dict: name → SkillMeta）

### 3.2 注册表（Registry）

- `load_skill(name)` → 完整加载 skill 内容
- `load_meta(name)` → 三层合并：`SKILL.md` < `.skill-meta.yaml`（LLM 抽，带 `_meta_cache`） < `.skill-local.yaml`（用户覆写）
- 缓存 key=name，失效盯 `.skill-local.yaml` 的 mtime

### 3.3 路由（Router V0.3）⚠️ 已重构

```python
from skill_engine.routing.router import Router
plan = router.match(query, llm=llm, top_k=3)   # → MatchPlan
# plan.mode ∈ {"single","multi"}; plan.primary / plan.selections / plan.method / plan.score
runner.run(plan)   # 支持单/多 skill
```

**三步路由（砍 embedding）：**
1. **精确**：name / alias / shortcut 匹配（score=1.0）→ `MatchPlan(mode=single)`
2. **纯英文 exact 没中** → 跳 keyword 直进 LLM
3. **中文/中英混**：结巴分词 + intention 加权打分
   - 0 命中 → LLM 兜底
   - 单候选 ≥0.7 → 直接返
   - 多候选/低分 → LLM 决定（单/多 skill）

**预处理（Preprocessor）**：lazy 在首次 `load_meta` 时调 LLM 抽 `.skill-meta.yaml`（intention/synonyms/keywords），带 `source_hash` 增量。无 preprocessor 时 `score_keyword` 给 0 分，自动进 LLM 兜底。

> 详细设计见 `skill路由优化方案.md`（2026-07-28）。

### 3.4 执行（Runner）

- `run_skill(name, llm=None, **args)`：按名字执行（code-tutor-agent 主用通道）
- `run(plan)`：按 `MatchPlan` 单/多 skill 分流
- 4 路分流：`llm`（单次 LLM 生成）/ `steps`（Steps DSL 编排）/ `orchestrator`（LangGraph）/ `auto`（按 skill 类型自动选）
- 输出归一为 `SkillResult`（`.ok` / `.output` / `.error` / `.meta`）

### 3.5 创建（Creator + Designer，Phase 11）

```bash
skill-engine create "帮我写一个分析 Python 代码质量的 skill" [--name code-analyzer] [--dry-run]
```

- Designer：构造 prompt → LLM 生成 JSON design（3 层 JSON 容错）→ 校验
- Creator：纯机械写 `SKILL.md` / `scripts/` / `assets/`
- Validator：编译验证 + 脚本引用检查（零重试 MVP）

> 详细设计见 `phase11-llm-native-design.md`（2026-07-27）。

### 3.6 命令行（CLI，10 个命令）

| 命令 | 作用 |
|------|------|
| `list` | 列出所有 skill（名称/描述/分组） |
| `info <name>` | 查看 skill 详情 |
| `match "<query>"` | 自由文本路由匹配（`--explain` 看打分） |
| `scan` | 扫描并列出 skill 路径 |
| `clear-cache` | 清注册表缓存 |
| `run <name>` | **按名执行**（`-a "k=v"` / `--llm` / `--dry-run`） |
| `install/uninstall/update` | skill 安装管理 |
| `index` | 显式触发 Preprocessor 全量/增量抽 `.skill-meta.yaml`（`--rebuild-meta` 强制） |

> 注：自由文本 `match` 依赖 tokenize + preprocessor；在 `jieba` 未装 / 无 LLM 的环境里关键词打分为 0，会进 LLM 兜底但可能返回空——这是路由共性问题，**按名 `run` 不受此影响**。

## 四、三种执行模式对比

| 模式 | 入口 | 何时用 | 特点 |
|------|------|--------|------|
| **Interactive** | `ui.py`（Gradio） | 人工试用 skill | 有 Web 界面，5 个 Tab |
| **CLI** | `cli.py run <name>` | 脚本/agent 调用 | 子进程隔离，最稳 |
| **Library** | `import skill_engine` | 程序内嵌 | `discover` / `Router` / `run_skill` 直接调用 |

**关键决策**：CLI 模式作为 code-tutor-agent 的「逃生舱」保留（adapter 主通道失败时降级），详见下一章。

## 五、与 code-tutor-agent 的接入（CTA Skills 套件）

code-tutor-agent 把「出题 / 出题解 / 出测试用例」三块逻辑封装为本引擎的 3 个 skill（见 `skills/cta-generate-*`），并通过 **editable 安装**（`pip install -e skill-engine`）接入其 venv。

### 5.1 三个 CTA Skill

| Skill | 职责 | 对应 code-tutor-agent 逻辑 | 运行方式 |
|-------|------|--------------------------|----------|
| `cta-generate-problem` | 出题 | `ProblemAgent` → `engine_adapter.run_skill` / `parse_problem_markdown` | skill-engine `run`（adapter / cli 通道） |
| `cta-generate-solution` | 出题解（文字讲解 + 最优代码 + 暴力代码） | `generate_detailed_solution` → `engine_adapter.generate_detailed_solution` | skill-engine `run`（adapter / cli 通道） |
| `cta-generate-test-cases` | 出测试用例（参考解 oracle 实跑回填） | `generation._generate_complex_tests`（参考解 oracle + 随机/边界用例） | Steps DSL（`generate`+`read_result`），`skill-engine run cta-generate-test-cases` 一次出 `test_cases.json`；完全自包含，不依赖 code_tutor_agent |

> 运行命令见 `skill执行命令指南/cta skill 执行指南.md`。

### 5.2 双通道（adapter 主 / cli 逃生舱）

code-tutor-agent 调用 CTA skill 有两条路径，结果同形为 `SkillResult`：

- **adapter（主通道，进程内）**：`engine_adapter.run_skill(name, **args)` 直接 import 本引擎并调用 `run_skill`，无子进程开销。
- **cli（逃生舱）**：`skill_cli.run_skill_cli(name, args)` 子进程 `skill-engine run <name> -a "..." --llm`，受 `SKILL_ENGINE_CLI_ALLOWLIST` 白名单约束（当前默认 `cta-generate-problem,cta-generate-solution`）。

### 5.3 出题降级链（ProblemAgent）

```
ProblemAgent.generate(topic, difficulty)
   ├─ 1) LLM 结构化出题 (with_structured_output(Problem) + verify_problem 自校验)  → ProblemChannel.LLM
   ├─ 2) adapter 通道: engine_adapter.run_skill("cta-generate-problem")             → ProblemChannel.ADAPTER
   ├─ 3) cli 通道:    skill_cli.run_skill_cli("cta-generate-problem")               → ProblemChannel.CLI
   └─ 4) 静态题库兜底 get_static_problem()                                          → ProblemChannel.STATIC
```

- 出题产物经 `skills/parser.parse_problem_markdown`（adapter/cli 共用）解析为标准分节：`## Title / Topic / Difficulty / Description / Examples / Constraints / StarterCode / FunctionSignature / BruteSolution / OptimalSolution`。

## 六、已知问题（2026-07-28 现状）

- `jieba` 是 `tokenize` 可选依赖；未装时中文自由文本 `match` 退化为 LLM 兜底（不影响按名 `run`）。
- `run` 命令扫描 `Path.cwd()/"skills"`，**必须在 skill-engine 根目录运行**；code-tutor-agent 经 `get_skill_engine_dir()` 配置正确指向根目录。
- Phase 11 LLM 模式端到端（`create` 实跑）待验证；`--dry-run` 已可查看 LLM 原始输出。
- CTA `cta-generate-test-cases` 当前仅以脚本形式被直接调用，尚未接入 `SKILL_ENGINE_CLI_ALLOWLIST` 与 `engine_adapter`（未来工作）。

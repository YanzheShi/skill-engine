```
用户输入
    │
    ▼
┌─────────────────┐
│   discovery     │  扫描多路径，建立 SkillMeta 索引
│   (发现)        │  优先级: 用户级(10) < 项目级(20) < 自定义(30)
└───────┬─────────┘
        │
        ▼
┌─────────────────┐
│   registry      │  管理索引、缓存 Skill 对象、懒加载 body
│   (注册表)      │  提供分组、state 过滤、热加载接口
└───────┬─────────┘
        │
        ▼
┌─────────────────┐
│   router        │  4 种匹配方法
│   (匹配器)      │  name / keyword / embedding / llm
└───────┬─────────┘
        │ MatchResult 列表
        ▼
┌──────────────────────────────────────┐
│   runner (执行器)                     │
│                                      │
│   run()  ── 4 路分流:                 │
│   ├─ steps ≠ None   → Steps DSL      │
│   ├─ tool_dispatch  → 档位 B         │
│   ├─ llm            → 档位 A         │
│   └─ 默认            → 纯编译        │
│                                      │
│   run_orchestration() ── 多 skill 编排 │

└───────┬──────────────────────────────┘
        │
        ├── assembler  → 编译 body（!cmd 替换、参数替换、ref 注入）
        │
        └── executor   → 沙箱执行（超时、白名单、PATH 限制）

## 三、各模块详解

### 3.1 discovery — Skill 发现

**扫描路径顺序（优先级从低到高，同名高优先覆盖低优先）：**

| 优先级 | 路径 | 说明 |
|--------|------|------|
| 10 | `~/.agents/skills/` | 通用 Agent Skills 标准路径 |
| 10 | `~/.claude/skills/` | Claude Code 标准路径 |
| 10 | `~/.skill-engine/skills/` | skill-engine 用户级 |
| 20 | `.claude/skills/` | 项目级 Claude Code |
| 20 | `.skill-engine/skills/` | 项目级 skill-engine |
| 30 | 自定义 roots（参数传入） | 最高优先级 |

**核心函数：**

- `_parse_frontmatter(content)` → `(dict, str)` — 解析 SKILL.md 的 YAML frontmatter + Markdown 正文
- `_discover_skill_dir(dir_path, priority)` → `{name: SkillMeta}` — 扫描单个目录下所有含 SKILL.md 的子目录
- `discover(roots, overrides, skip_defaults)` → `{name: SkillMeta}` — 多根目录发现，支持 state 覆盖和测试隔离

**输出：** `SkillMeta` — 轻量元数据（name, description, directory, priority, state），不含 body

### 3.2 registry — 注册表

- `list_names()` — 所有 skill 名称（不受 state 过滤）
- `list_active()` — state != "off" 的 skill 名称
- `info(name)` → `SkillMeta` — 元数据查询
- `info_full(name)` → `dict` — 仅解析 frontmatter，不读 body（比 load_skill 轻量，适合 catalog 构建）
- `load_skill(name)` → `Skill` — 懒加载完整 Skill 对象（含 body），缓存命中直接返回
- `get_groups()` → `{group_name: [skill_name]}` — 按 groups 字段分组
- `invalidate(name)` / `clear_cache()` — 缓存管理

**缓存机制：** `load_skill` 返回的 Skill 对象缓存到 `_cache` 字典，后续调用直接返回同一对象。`clear_cache()` 清空所有缓存。

### 3.3 router — 匹配器

**4 种匹配方法：**

| 方法 | 原理 | 评分 |
|------|------|------|
| `name` | 精确匹配 skill 名称（大小写不敏感） | 1.0 或 0 |
| `keyword` | 关键词匹配 description + when_to_use | 累加，上限 1.0 |
| `embedding` | sentence-transformers 余弦相似度 | 0~1.0 |
| `llm` | 构造 prompt 让 LLM 打分，解析 JSON | 0~1.0 |

**keyword 评分规则：**
- description 中包含关键词：+0.5/个
- when_to_use 中包含关键词：+0.3/个
- 完全匹配（整个 query 在 description 中）：+0.8
- 上限 1.0

**LLM 匹配 prompt：** 构造包含所有可用 skill 的 name+description+when_to_use+groups 的列表，让 LLM 返回 JSON `{matches: [{skill, score, reason, arguments}], overall_reasoning}`

### 3.4 executor — 执行器（沙箱）

- `run_preprocess(command, cwd)` — 宽松模式，给 Assembler 用（不检查白名单）
- `run_step(command, cwd)` — 严格模式，给 Runner 用（检查白名单）

**安全措施：**
- 超时控制（默认 10s，可配置）
- 白名单（默认允许 python, python3, cat, echo, curl, git, head, tail, wc, mkdir, touch）
- MVP 阶段 `allow_all=True`，略过白名单检查
- 输出大小限制（1MB）
- 环境变量沙箱（PYTHONUNBUFFERED, PATH 限制）

### 3.5 assembler — 编译器

**编译流程（6 步）：**

1. **注入目录路径变量** — `${SKILL_DIR}`, `${SKILL_SCRIPTS_DIR}`, `${SKILL_ASSETS_DIR}`
2. **动态注入 !command** — 执行 `` !`cmd` `` 行内语法和 ` ```! ` 代码块语法，结果替换到 body 中
3. **参数替换** — `$ARGUMENTS`, `$0`, `$1`, `$name` 等变量替换
4. **加载支持文件 refs** — `[REF: filename]` 语法，将文件内容注入 body
5. **注入宪法切片** — 全局约束规则（可选）
6. **包装** — `[SKILL: name]\n{body}`

### 3.6 runner — 执行器

**`run()` — 4 路分流：**

| 路径 | 条件 | 行为 |
|------|------|------|
| 1. Steps DSL | `steps is not None` | 确定性步骤执行（exec/llm/write/read） |
| 2. 档位 B | `tool_dispatch` 不为空 | LLM→tool_call→Executor→LLM 循环 |
| 3. 档位 A | `llm` 不为空 | 单次 LLM invoke |
| 4. 纯编译 | 默认 | 只输出 compiled prompt |

**档位 B 支持的工具类型：**
- `bash` — 执行 shell 命令
- `read_file` — 读取文件内容
- `write_file` — 写入文件
- `stop` — 停止执行，返回原因

**`run_orchestration()` — 多 skill 编排：**

流程：
1. 构建 skill 目录（catalog）— 按 groups 分组展示 frontmatter 元数据
2. 构建编排 prompt，调 LLM 规划
3. LLM 返回 JSON `{plan: [{skill, args, description}], reasoning}`
4. 按编排链依次执行 `_execute_chain()`，前一步输出通过 `prev_outputs` 传给下一步
5. 汇总结果

**`create_skill()` — 自动创建：**
1. 调用 SkillCreator 创建目录 + SKILL.md + scripts/
2. 调用 SkillValidator 验证
3. 热注册到 registry

### 3.7 orchestrator — LangGraph 编排器

基于 LangGraph StateGraph 的编排器，与 `runner.run_orchestration()` 功能等价。

**状态图：**

```
plan → should_continue → execute → plan → ... → format → END
         ├─ direct_answer → format
         └─ max_planning_steps → format
```

**节点：**
- `plan_node` — 调 LLM 决定用哪些 skill
- `execute_chain_node` — 按链依次执行各 skill
- `format_result_node` — 格式化输出
- `should_continue_node` — 条件路由

**状态：** `OrchestrationState` — TypedDict，包含 user_input, catalog, plan, chain_results, all_outputs, files_created 等

### 3.8 creator — Skill 自动创建 + 验证

**SkillCreator.create(name, description, ...)**
1. 创建 skill 目录
2. 生成 YAML frontmatter + Markdown body → SKILL.md
3. 生成 scripts/ 目录（可选）
4. 验证

**SkillValidator**
- `validate_compile(skill)` — Assembler 编译验证
- `validate_scripts(skill)` — 脚本引用验证
- `full_validate(skill)` — 完整验证

### 3.9 config — LLM 配置

**6 个模型别名：**

| 别名 | 环境变量 | 用途 |
|------|----------|------|
| agnes | AGNES_MODEL, AGNES_BASE_URL, AGNES_API_KEY | 主模型 |
| agnes-stream | 同上 + streaming=True | 流式模型 |
| sensenova | SENSENOVA_MODEL1, SENSENOVA_BASE_URL, SENSENOVA_API_KEY | 商汤 |

`get_llm(alias, **kwargs)` — 用 `langchain.chat_models.init_chat_model` 创建 LLM 实例

### 3.10 CLI — 命令行接口

9 个命令（Typer）：

```
skill-engine list [-v]              # 列出所有 skills
skill-engine info <name>             # 查看 skill 详情
skill-engine match <query>           # 匹配 skills（--method, --top-k）
skill-engine scan [--root DIR]       # 扫描并显示发现的 skills
skill-engine clear-cache             # 清空缓存
skill-engine run <query>             # 执行 skill（--method, --llm, --tool-dispatch, --dry-run, --args）
skill-engine install <source>        # 安装 skill（本地路径 / Git URL / npx:）
skill-engine update <name>           # 更新 skill
skill-engine uninstall <name>        # 卸载 skill
```

**run 命令匹配逻辑：** 3 分支
1. `--args` 不为空 → query_or_name 是 skill name，精确匹配 name
2. `--method` 指定 → 按指定方法匹配，匹配不到时 fallback 到 name 精确匹配
3. 默认 → fallback 链：name → keyword → llm

### 3.11 UI — Gradio Web UI

5 个 Tab：
1. **Skill 列表** — 展示所有已安装 skills（分组显示）
2. **Skill 匹配** — 输入查询，展示匹配结果（支持 keyword/name/llm 方法）
3. **直接执行** — 输入查询，自动匹配并执行（支持 compile/llm/dry-run 模式）
4. **手动执行** — 选择 skill 执行（支持 args + 多种模式）
5. **管理** — 安装/卸载 skills

### 3.12 models — 数据模型

| 模型 | 说明 |
|------|------|
| `SkillMeta` | 轻量元数据（dataclass），name, description, directory, priority, state |
| `SkillMetadata` | 完整 frontmatter 元数据（Pydantic），所有 CC 规范字段 |
| `Skill` | 完整 skill 对象，metadata + body + directory + supporting_files |
| `MatchResult` | 匹配结果，skill + score + method + arguments |
| `Step` | Steps DSL 中的一步，name + type + command/url/template/output_file |
| `SkillOverride` | skillOverrides 配置，skill_name + state |
| `SkillContext` | 枚举，INLINE / FORK |

## 四、数据流

```
SKILL.md (磁盘文件)
    │
    ├── discovery._parse_frontmatter()
    │   → SkillMeta (name, description, directory, priority, state)
    │
    ├── registry.load_skill()
    │   → Skill (metadata + body + supporting_files)
    │
    ├── router.match()
    │   → MatchResult (skill + score + method + arguments)
    │
    ├── assembler.assemble()
    │   → final_prompt (body + !cmd 替换 + 参数替换 + ref 注入 + 宪法切片)
    │
    └── executor.run_step()
        → {stdout, stderr, exit_code, timed_out}
```

## 五、执行模式对比

| 模式 | 触发条件 | 执行方式 | 适用场景 |
|------|----------|----------|----------|
| 纯编译 | 默认 | 只输出 prompt | pipe 给外部工具 |
| 档位 A | `--llm` | 单次 LLM invoke | leetcode-solution-writer 等 fetch→LLM→save |
| 档位 B | `--tool-dispatch` | LLM→tool_call→Executor 循环 | 对话型 skill（grill-me, algorithm-interviewer） |
| Steps DSL | SKILL.md 定义 steps | 确定性步骤执行 | 固定流程的任务 |
| 编排 | `run_orchestration()` | LLM 规划→链式执行 | 复杂需求，多 skill 协同 |

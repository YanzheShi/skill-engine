# 代码审查检查清单（审查基准）

审查时按以下维度逐项核对，发现问题按严重级别归类。

## 严重级别定义

| 级别 | 定义 | 示例 |
|------|------|------|
| 🔴 阻断 (Blocker) | 功能不可用、数据错误、安全漏洞、崩溃 | 登录必现 500、SQL 注入、金额计算错误 |
| 🟠 严重 (Critical) | 主要功能明显偏离需求、核心路径有缺陷 | 需求的功能没实现、超时无兜底 |
| 🟡 一般 (Major) | 边界未处理、异常未处理、性能隐患 | 空输入崩溃、N+1 查询、并发竞态 |
| 🟢 建议 (Minor) | 可读性、命名、可维护性 | 变量名含糊、重复代码、死代码 |

## 需求符合度核对

- [ ] 每条需求条目是否都能在实现中找到对应位置（找不到 = 未实现）
- [ ] 实现行为与需求描述是否一致（参数、默认值、返回值、处理逻辑）
- [ ] 需求约定的边界条件是否覆盖（空输入、超长、并发、异常流、权限）
- [ ] 错误处理与需求约定的错误提示/降级行为是否一致
- [ ] 需求中明确"不支持/不处理"的场景是否真的未实现
- [ ] 输入校验与需求定义的约束是否一致（类型、长度、格式、取值范围）

## UI/设计稿核对（前端）

- [ ] UI 元素是否齐全（按钮、表单字段、弹窗、区块、导航）
- [ ] 样式是否与设计稿一致（间距、颜色、字号、圆角、阴影）
- [ ] 交互状态是否实现（hover、点击态、loading、禁用态、错误态、空态）
- [ ] 文案是否与设计稿一致
- [ ] 响应式/断点是否处理（移动端、窄屏）
- [ ] 图片/图标资源是否存在且被正确引用（无 404）
- [ ] 表单校验提示与稿子一致（位置、文案、触发时机）

## 质量检查项

- [ ] 命名是否清晰
- [ ] 是否有适当的注释/docstring
- [ ] 函数是否单一职责
- [ ] 是否有重复代码
- [ ] 异常处理是否完善（吞异常、裸 except）
- [ ] 是否有死代码/未使用变量/未使用导入

## 安全检查项

- [ ] 是否有 SQL 注入风险（拼接查询、参数化缺失）
- [ ] 是否有 XSS 风险（未转义输出、innerHTML 直插）
- [ ] 敏感信息是否泄露（硬编码密钥、日志打印密码/token）
- [ ] 输入是否验证（越权、路径穿越、文件上传限制）
- [ ] 认证/授权是否缺失或绕过（接口未鉴权、越权访问）

## 性能检查项

- [ ] 是否有 N+1 查询
- [ ] 是否有不必要的循环/重复计算（可缓存机会）
- [ ] 内存使用是否合理（大对象长期持有、泄漏）
- [ ] 是否有明显可避免的同步阻塞（同步 IO 热点路径）

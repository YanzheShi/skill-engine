# 数字孪生输入规范（Digital Twin Input Spec）

> 本文件定义候选人需要准备的"深度输入材料"的标准格式。
> 这些材料存放在 `resume/` 目录下，
> Skill 会在面试前自动读取并构建候选人的"数字孪生"画像。

---

## 一、文件清单与优先级

```
resume/
├── resume.md                          # 【必须】简历原文
├── project-deep-dive/                # 【强烈推荐】项目防拷打档案
│   ├── project-1-rag.md
│   ├── project-2-agent.md
│   └── project-3-finetune.md
├── self-assessment.json              # 【必须】个人能力自评矩阵
├── target-jd/                        # 【推荐】目标岗位 JD
│   └── jd-1.md
├── prompt-logs/                      # 【可选】Prompt 调优日志
│   └── chatbot-prompt-v1-to-v5.md
└── online-cases/                     # 【可选】线上真实 Bad Case
    ├── case-1-hallucination.md
    ├── case-2-agent-loop.md
    └── case-3-recall-dirty-data.md
```

## 二、项目防拷打档案模板

> 每个项目一个文件，存放在 `resume/project-deep-dive/` 目录下。
> 这是面试中**最关键的输入**——Skill 会据此进行精准追问和压力测试。

### 模板：`project-N-{name}.md`

```markdown
# 项目：{项目名称}

## 1. 基本信息
- 项目周期：{起止时间}
- 你的角色：{负责人/核心开发/参与者}
- 团队规模：{几人}
- 用户规模：{DAU/PV/内部使用人数}

## 2. STAR 完整叙事（用于面试前的自检）
- **Situation**：业务背景是什么？为什么需要这个项目？
- **Task**：你个人被分配/主动承担的具体任务是什么？
- **Action**：你做了哪些关键决策？技术选型过程？
- **Result**：最终效果如何？**用精确数字**（延迟从X→Y、准确率X%、成本节省X%）

## 3. 技术选型对比（核心！面试官最爱问）
对每个关键选型，写出真实权衡过程：

### 选型决策 1：{例如 RAG 框架}
- 候选方案：LangChain / LlamaIndex / 自研
- 最终选择：{X}
- 选择理由：{为什么选 X，不用 Y}
- 不选 Y 的原因：{具体原因，不是"感觉 X 好"}
- 事后验证：{选对了还是选错了？如果重选会怎样？}

### 选型决策 2：{例如 向量数据库}
- 候选方案：Milvus / Chroma / PGVector / Qdrant
- 最终选择：{X}
- 数据量：{多少文档、多少向量、维度多少}
- 选择理由：{性能/成本/运维/团队熟悉度}
- 踩坑记录：{迁移过程中遇到的具体问题}

## 4. 踩坑与解决方案（至少写 3 个）
每个坑按以下格式：

### 坑 1：{标题}
- **现象**：{什么问题？什么场景下触发？}
- **排查过程**：{你是怎么定位到根因的？用了什么工具？}
- **根因**：{到底是什么问题？}
- **解决方案**：{怎么修的？}
- **量化效果**：{修复前后对比数字}
- **如果重做**：{你会提前做什么来避免这个坑？}

## 5. 失败与反思
- 项目中最让你痛苦/崩溃的瞬间：{描述}
- 你做过的"错误决策"：{是什么？为什么当时做了？}
- 如果从头再来，你会改变的三件事：
  1. {改变 1}
  2. {改变 2}
  3. {改变 3}

## 6. 关键指标清单
- 核心业务指标：{例如 用户满意度、留存率}
- 技术指标：{例如 召回率、延迟、吞吐、成本}
- 评测方法：{怎么测的？谁定义的指标？}
- 数据来源：{指标从哪来？监控系统？人工标注？}

## 7. 面试官可能挖的坑（自检清单）
> 自己先列出 5-10 个最怕被问的问题，提前准备好答案

1. "为什么不直接用 {竞品/开源方案}？"
2. "如果流量翻 10 倍你的系统哪里会挂？"
3. "你的召回率 {X}% 是怎么算的？测试集多大？"
4. "项目上线后用户最大的投诉是什么？"
5. "你在项目里写代码的时间占多少？大部分时间在干什么？"
```

### 评分标准

| 分数 | 含义 | 面试策略 |
|---|---|---|
| 9-10 | 精通 | 深挖到论文级细节，验证是否真懂 |
| 7-8 | 熟练 | 深挖工程实战，验证踩坑经历 |
| 5-6 | 熟悉 | 追问到第三层即可，找上限 |
| 3-4 | 了解 | **压力测试重点**——突然发难，逼出真实水平 |
| 1-2 | 小白 | 不主动问，但如果候选人吹牛则揭穿 |

> 文件位置：`resume/target-jd/jd-N.md`
> Skill 会解析 JD，与自评矩阵做 **Gap 分析**，生成定向 Mock 题。

```markdown
# {公司名} - {岗位名}

## 岗位要求（原文粘贴）
{...}

## 加分项（原文粘贴）
{...}

## 我的解析（候选人自评）
- 核心技能要求：{列出 3-5 个}
- 我匹配的项：{哪些我有经验}
- 我的 Gap：{哪些我没有/不够}
- 面试重点预测：{这个 JD 最可能考什么}
```

## 五、线上 Bad Case 记录

> 文件位置：`resume/online-cases/case-N-{topic}.md`
> 这些是**最值钱的面试素材**——真实踩坑比背八股管用 10 倍。

### 模板

```markdown
# Case N：{标题}

## 背景
{什么项目、什么时间、什么场景下发生的}

## 现象
{用户/监控发现了什么异常？}

## 排查过程
1. {第一步你做了什么}
2. {第二步}
3. {...}

## 根因
{最终定位到什么问题？}

## 解决方案
{怎么修的？短期+长期}

## 面试价值提炼
> 如果面试官问到这个领域，你可以用这个故事来证明：
> - 你的排查方法论
> - 你对这个技术的深度理解
> - 你的用户视角和业务意识
```

## 七、Skill 读取策略

1. **面试启动阶段**：读取 `resume.md` + `self-assessment.json` + 最新的 `target-jd/`
2. **项目深挖阶段**：读取对应项目的 `project-deep-dive/` 文件
3. **追问生成阶段**：读取该项目的"踩坑记录"和"选型对比"，生成**只有真做过才答得出来**的追问
4. **压力测试阶段**：根据自评矩阵中 3-4 分的项，**突然发难**
5. **报告生成阶段**：读取所有材料，做 Gap 分析 + 黄金话术对比
6. **防作弊机制**：Skill **不会直接引用档案里的答案**，而是用档案里的"坑"来设计**反向问题**——
   比如档案里写了"我们用 Milvus 不选 PGVector 是因为数据量超过 100 万"，
   Skill 会问"如果只有 10 万数据你还用 Milvus 吗？"来验证真实性

## 一、RAG（检索增强生成）

### Q1：请完整描述一个生产级 RAG 系统的全流程

**考察维度**：项目深度 / 架构思维
**预期深度**：第三层（能说出每一步的工程取舍和踩坑）

**追问路径**：
1. "文档解析阶段，PDF 里的表格和图片你怎么处理？"
2. "分块策略你用固定大小还是语义分块？chunk_size 怎么定的？"
3. "检索阶段为什么选向量检索？有没有试过 BM25 或混合检索？"
4. "召回了 20 条，怎么决定喂给 LLM 几条？上下文窗口怎么管理？"
5. "生成阶段幻觉怎么控制？有没有做 citation / grounded generation？"
6. "端到端怎么评测？RAGAS 你用过吗？"

**常见翻车点**：
- 只说"用 LangChain 搭的"就停了 → 第一层，记薄弱
- 不知道 chunk_size 太大太小各有什么后果
- 说不出混合检索（Hybrid Search）和 Rerank 的存在
- 评测只说"人工看看还行" → 缺乏工程化意识

### Q2：RAG 的召回率不好，你怎么排查和优化？

**考察维度**：问题排查 / 工程实战
**预期深度**：能给出系统化的排查链路

**标准答案框架**：
```
1. 先看数据层：文档解析是否丢内容？分块是否合理？
2. 再看检索层：Embedding 模型是否适配领域？query 是否需要改写/扩展？
3. 然后看召回策略：Top-K 够不够？是否需要混合检索？
4. 最后看重排：是否引入 Cross-Encoder Rerank？
5. 端到端：用 RAGAS / 人工标注 评估各阶段漏斗
```

**加分项**：能说出具体数字（"召回率从 71% → 89%"）、用过具体工具（RAGAS、LlamaIndex、Milvus）

### Q3：RAG vs 微调（Fine-tuning），你怎么选型？

**考察维度**：技术选型 / 业务思维
**预期深度**：四维度对比 + 场景化决策

**加分回答框架**：

| 维度 | RAG | 微调 |
|---|---|---|
| 数据新鲜度 | ✅ 实时更新知识库 | ❌ 需重新训练 |
| 可解释性 | ✅ 有引用来源 | ❌ 黑盒 |
| 定制化深度 | 中等 | ✅ 深度适配 |
| 成本 | 低（API 调用） | 高（训练+部署） |
| 适用场景 | 知识问答、文档助手 | 风格迁移、特定任务优化 |

**金句加分**："如果模型不知道某个事实 → RAG；如果模型知道但说不好 → 微调。"

## 二、Agent 与工具调用

### Q4：什么是 Agent？Agent Loop 的执行流程是什么？

**考察维度**：核心概念 / 架构理解
**预期深度**：能画出/描述完整的 ReAct 循环

**标准答案要点**：
```
Agent = LLM + 工具(Tools) + 规划(Planning) + 记忆(Memory)

执行循环：
1. 接收用户任务
2. LLM 推理：下一步该调用什么工具？
3. 执行工具调用（Tool Call）
4. 观察工具返回结果（Observation）
5. 判断是否完成任务 → 是则输出，否则回到步骤 2
```

**追问**：
- "Agent 和 Workflow 的本质区别是什么？"（Agent 是动态决策，Workflow 是固定编排）
- "Agent 容易陷入无限循环怎么办？"（最大步数限制、反思机制、Human-in-the-loop）
- "多 Agent 协作你怎么设计？"（角色分工、通信协议、任务路由）

---

### Q5：Function Calling / Tool Use 的原理是什么？模型怎么决定调用哪个工具？

**考察维度**：原理理解 / 实现细节
**预期深度**：能说出训练方式和推理流程

**要点**：
- 工具定义以 JSON Schema 形式注入 System Prompt
- 模型输出特殊 token（如 `<|tool_call|>`）触发工具调用
- 通过 SFT + RL 训练模型学会"何时调用 + 调用哪个 + 参数怎么填"
- 推理时解析模型输出 → 执行工具 → 结果回填到上下文 → 模型继续生成

**常见翻车**：说不清"模型输出的是工具调用指令还是真的执行了"（模型只输出指令，执行在外部）

### Q6：Agent 的 Memory 机制你怎么设计？

**考察维度**：系统设计 / 生产经验
**预期深度**：分层记忆 + 具体实现方案

**加分框架**：
```
短期记忆：当前对话上下文（Context Window）
  → 滑动窗口 / 摘要压缩 / 重要信息提取

长期记忆：跨会话持久化
  → Vector Store（语义检索历史）
  → Key-Value Store（用户偏好、事实）
  → 结构化数据库（重要决策记录）

记忆管理策略：
  → 写入时：重要性评分 + 去重 + 摘要
  → 读取时：相关性检索 + 时间衰减 + 容量控制
```

## 三、Transformer 与注意力机制

### Q7：手推 Self-Attention 的计算过程

**考察维度**：基础八股 / 数学功底
**预期深度**：能写出完整公式并解释每一步

**标准流程**：
```
1. 输入 X → 线性变换 → Q, K, V
2. 计算注意力分数：scores = QK^T / sqrt(d_k)
3. Softmax 归一化 → attention weights
4. 加权求和：output = weights × V
5. 多头拼接 + 线性变换
```

**必须说清的点**：
- 为什么要除以 `sqrt(d_k)`？（防止点积过大 → softmax 梯度消失）
- Q、K、V 分别是什么？（Q=查询，K=键，V=值，类比检索）
- 时间复杂度 O(n²d)，空间复杂度 O(n²) 的瓶颈在哪？

**加分**：能画出矩阵维度变化、能对比 MHA / MQA / GQA 的内存差异

### Q8：Transformer 的 Position Encoding 有哪些方案？各有什么优劣？

**考察维度**：原理深度 / 技术广度
**预期深度**：至少说出 3 种方案并对比

| 方案 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| 正弦位置编码 | 固定公式生成 | 可外推到更长序列 | 表达能力有限 |
| 可学习位置编码 | 训练得到 | 灵活 | 无法外推 |
| RoPE（旋转位置编码） | 旋转矩阵编码 | 优秀的外推性 | 实现稍复杂 |
| ALiBi | 注意力偏置 | 简单、外推好 | 相对较新 |

**加分**：能说出"为什么 LLAMA / Qwen 用 RoPE"、"长度外推（NTK-aware / YaRN）怎么做"

## 四、模型微调与部署

### Q9：LoRA 的原理是什么？为什么它比全量微调更高效？

**考察维度**：微调原理 / 工程实践
**预期深度**：数学原理 + 工程优势 + 超参经验

**标准答案**：
```
核心思想：在原始权重 W 旁新增低秩分解矩阵 BA
  W' = W + BA（其中 B∈R^{d×r}, A∈R^{r×k}, r << d）

优势：
1. 训练参数少（r=8 时约 0.1% 参数量）
2. 不修改原始权重，可热插拔多个 LoRA 适配器
3. 显存占用低，单卡可训
4. 推理时合并权重，零延迟开销
```

**追问**：
- "LoRA 的 rank 怎么选？太大太小会怎样？"（经验值 8-64）
- "LoRA 和 QLoRA 的区别？"（QLoRA = LoRA + 4bit 量化基座，显存再降）
- "Prefix Tuning / Adapter / LoRA 怎么选？"

---

### Q10：RLHF 的三阶段流程是什么？DPO 相比 RLHF 有什么改进？

**考察维度**：训练范式 / 前沿追踪
**预期深度**：能说清每个阶段在做什么、为什么需要

**RLHF 三阶段**：
```
1. SFT（监督微调）：用标注数据教模型"怎么说"
2. Reward Model 训练：训练一个打分模型，给回答打偏好分
3. PPO 优化：用 RM 的奖励信号 + KL 约束，RL 优化策略模型
```

**DPO 的核心改进**：
- 把 RLHF 的"训练 RM + PPO 优化"合并为一步
- 直接利用偏好数据（chosen vs rejected）做分类损失
- 不需要 RM、不需要 PPO、训练更稳定

**加分**：能说出 DPO 的局限性（对噪声偏好数据敏感、缺乏显式奖励值）

## 六、编码能力题（第1轮常考）

### Q13：实现一个简化版的 Self-Attention（PyTorch）

**考察维度**：代码能力 / 原理理解
**预期深度**：能写出可运行版本 + 解释维度

```python
import torch
import torch.nn.functional as F

def self_attention(Q, K, V, mask=None):
    """
    Q, K, V: (batch, seq_len, d_k)
    mask: (batch, seq_len) 可选
    """
    d_k = Q.size(-1)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)
    
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    
    attn_weights = F.softmax(scores, dim=-1)
    output = torch.matmul(attn_weights, V)
    return output, attn_weights
```

## 七、加分前沿题（资深岗 / 第2-3轮）

### Q15：MCP（Model Context Protocol）是什么？解决什么问题？

**要点**：
- Anthropic 提出的开放协议，标准化 LLM 与外部工具/数据源的连接
- 解决"每个工具都要单独适配"的碎片化问题
- 类比：USB-C 统一接口 → MCP 统一工具协议

### Q16：Agentic RAG 和传统 RAG 有什么区别？

**要点**：
- 传统 RAG：检索 → 生成，固定流水线
- Agentic RAG：Agent 动态决定"是否检索、检索什么、检索几次"
- 支持多跳检索、跨文档推理、自适应查询改写

### Q17：大模型推理优化有哪些手段？（vLLM / TensorRT-LLM / 量化）

**要点**：
- 连续批处理（Continuous Batching）
- PagedAttention（显存分页管理）
- KV Cache 量化（INT8 / INT4）
- 模型量化（GPTQ / AWQ / SmoothQuant）
- 投机解码（Speculative Decoding）

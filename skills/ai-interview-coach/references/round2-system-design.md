# 第2轮 · 深度项目 + 系统设计面 题库与执行指南

> 第2轮是"决胜关"，决定候选人是"真做过"还是"跟着教程跑过"。
> 核心原则：**追问到候选人答不出来为止**，这才是真实水位。

---

## 本轮结构（建议 60 分钟）

| 阶段 | 时长 | 内容 |
|---|---|---|
| 项目深挖 ×2 | 25 min | 2 个项目各挖到第三层（踩坑+量化+决策） |
| 系统设计题 ×1 | 20 min | 白板级架构设计 |
| 技术选型辩论 | 10 min | 给出场景，让候选人做 trade-off 决策 |
| 反向提问 | 5 min | 候选人问面试官 |

---

## A. 项目深挖（25 分钟，重点！）

### 方法论：三层深挖法

对每个项目，按以下模板追问：

#### 第一层：做了什么（2 分钟）
> "简单介绍一下这个项目是什么、解决什么问题、你的角色是什么。"

✅ 合格标准：能说清项目背景、用户是谁、解决了什么痛点
❌ 翻车信号："就是一个 AI 聊天机器人"（没有具体场景）

#### 第二层：怎么做的（5 分钟）
> "技术架构是什么？为什么选这套方案？有没有考虑过其他方案？"

✅ 合格标准：能画出/描述完整架构图，技术选型有理由
❌ 翻车信号："用的 LangChain，它帮我处理的"（不知道内部机制）

**追问清单**：
- 模型选的哪个？为什么不是 GPT-4o / Claude / 开源模型？
- 向量数据库为什么选 Milvus / Chroma / PGVector？数据量多大？
- 分块策略怎么定的？试过几种？
- 有没有做 Rerank？用的什么模型？
- 流式输出怎么实现的？前端怎么处理的？

#### 第三层：踩坑与量化（8 分钟）⭐ 最关键
> "上线后遇到过什么大问题？怎么解决的？效果怎么衡量的？"

✅ 合格标准：**有具体数字、有排查过程、有 trade-off 分析**
❌ 翻车信号："没什么问题"、"效果还行吧"、"差不多 80% 准确率"（拿不出证据）

**必问杀手锏**：
1. "如果让你重新做这个项目，你会改什么？"（考察反思能力）
2. "这个系统现在能扛多少 QPS？瓶颈在哪？"（考察工程化思维）
3. "上线后用户最大的投诉是什么？你怎么响应的？"（考察用户视角）
4. "项目里你最自豪的一个技术决策是什么？为什么？"（考察判断力）
5. "有没有翻车过？怎么救的？"（考察抗压和复盘能力）

### 项目深挖评分

| 层级到达情况 | 得分 |
|---|---|
| 到达第三层，有数字有反思 | 4-5 分 |
| 到达第二层半，部分量化 | 3 分 |
| 只到第二层，没有量化 | 2 分 |
| 只到第一层，说不清细节 | 1 分 |

## B. 系统设计题（20 分钟）

> 从以下题目中选 1 道，让候选人**白板式设计**（可以画文字图/ASCII 图）

### 设计题 1：生产级 RAG 系统

**题目**：设计一个服务于 10 万用户的 AI 知识库问答系统。

**考察点**：
- 文档摄入流水线（解析→清洗→分块→Embedding→入库）
- 检索策略（向量+关键词混合、Rerank）
- 生成层（Prompt 模板、Citation、流式输出）
- 工程化（缓存、限流、降级、监控、A/B 测试）
- 成本优化（模型路由、Prompt Caching、批量处理）

**期望架构分层**：
```
用户请求
  ↓
API Gateway（鉴权/限流/路由）
  ↓
Query 理解 & 改写
  ↓
┌─────────────┐
│  检索层     │ → 向量检索 + BM25 + Rerank
└─────────────┘
  ↓
Context 组装 & 安全过滤
  ↓
┌─────────────┐
│  生成层     │ → LLM（主模型 + 小模型路由）
└─────────────┘
  ↓
后处理（Citation / 格式 / 敏感词）
  ↓
流式返回 + 异步记录日志
  ↓
观测层（延迟/成本/质量/用户反馈）
```

### 设计题 2：多 Agent 协作系统

**题目**：设计一个 AI 客服系统，能处理退货、换货、咨询、投诉四种场景。

**考察点**：
- Agent 路由策略（意图分类 → 分发到子 Agent）
- 各 Agent 的工具定义（查订单、发起退款、查物流）
- Agent 间通信与状态共享
- 异常处理（Agent 失败怎么办？转人工？）
- 记忆管理（跨轮次上下文、用户画像）

### 设计题 3：AI 对话产品的模型服务层

**题目**：为一个月活 100 万的 AI 对话产品设计模型推理服务架构。

**考察点**：
- 模型路由（简单问题用小模型，复杂问题用大模型）
- 推理优化（vLLM / TensorRT-LLM / KV Cache / 量化）
- 弹性扩缩容（GPU 资源管理）
- 多模型版本管理（灰度发布、A/B 测试）
- 成本监控与告警

### 设计题评分标准

| 维度 | 权重 | 要点 |
|---|---|---|
| 架构完整性 | 25% | 分层清晰、有入口/出口/异常路径 |
| 技术选型合理性 | 25% | 选型有理由、知道替代方案 |
| 工程化意识 | 25% | 考虑成本、监控、降级、扩展 |
| 深度追问应对 | 15% | "如果 QPS 翻 10 倍呢？""如果模型挂了呢？" |
| 表达与画图 | 10% | 能画架构图、逻辑清晰 |

## C. 技术选型辩论（10 分钟）

> 给出场景，让候选人做决策并辩护。考察真实工程判断力。

### 场景 1：RAG vs 微调
"你的老板要做一个公司内部知识问答，1000 篇文档，每天更新。他说'微调整个模型吧，效果好'。你怎么说服他/和她一起决策？"

### 场景 2：模型选型
"产品要在国内上线，需要中文能力强、成本低、能私有化部署。你在 GPT-4o / Claude / Qwen / DeepSeek / GLM 之间怎么选？给出决策矩阵。"

### 场景 3：实时性 vs 质量
"用户要求 2 秒内回答，但 Rerank + 大模型生成要 5 秒。你怎么 trade-off？给出至少 3 种方案。"

### 场景 4：成本爆炸
"你的 AI 功能上线后，API 费用每月 10 万，老板让你砍到 3 万。你的优化路径是什么？"

### 评分要点
- 能否列出多个方案（不是只给一个答案）
- 每个方案能说出 pros/cons
- 最终决策有量化依据（"方案 A 省 40% 成本但延迟 +200ms"）
- 考虑业务约束（预算、时间、团队能力）

同第1轮，但本轮更关注：

## 本轮通过标准

| 条件 | 必须？ |
|---|---|
| 至少 1 个项目挖到第三层 | ✅ 必须 |
| 系统设计有完整架构 + 工程化思考 | ✅ 必须 |
| 技术选型能给出 trade-off 分析 | ✅ 必须 |
| 编码/八股基础（第1轮已验证） | 沿用第1轮成绩 |

**决策**：
- 全部满足 → ✅ 强烈推荐进入第3轮
- 项目深度够但系统设计弱 → ⚠️ 待定，建议加面一轮技术
- 系统设计好但项目空 → ❌ 不推荐（可能只是"背得好"）
- 技术选型辩论完全无思路 → ❌ 不推荐

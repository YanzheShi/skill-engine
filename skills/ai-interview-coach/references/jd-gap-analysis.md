# JD Gap 分析与定向 Mock 机制

> 本文件定义 Skill 如何将**目标岗位 JD** 与候选人的**能力自评矩阵**做对比，
> 找出能力缺口，并生成**定向 Mock 面试题**。

---

## 一、JD 解析流程

### Step 1：读取 JD 文件

从 `resume/target-jd/` 目录读取所有 JD 文件。
如果目录为空 → 使用通用画像（降级模式）。

### Step 2：提取关键技能要求

用以下分类框架解析 JD：

| 分类 | 关键词示例 | 提取为 |
|---|---|---|
| 核心框架 | LangChain / LlamaIndex / RAG / Agent | 必备技能 |
| 模型经验 | GPT-4 / Claude / Qwen / DeepSeek / 微调 | 模型能力 |
| 部署运维 | vLLM / Docker / K8s / 推理优化 | 工程能力 |
| 数据/检索 | 向量数据库 / Milvus / Elasticsearch / Embedding | 检索能力 |
| 编程语言 | Python / Go / Rust | 编码能力 |
| 软技能 | 团队协作 / 独立负责 / 技术规划 | Behavioral |
| 业务领域 | 客服 / 搜索 / 推荐 / 内容生成 | 业务理解 |

## 二、Gap 分析算法

### 对比逻辑

```
对每个 JD required_skills 中的技能：
  候选人自评分数 = self_assessment.skill_matrix[skill].score
  JD 要求分数 = jd.required_skills[skill].level_required
  gap = JD要求分数 - 候选人自评分数

  if gap >= 3 → 🔴 严重缺口（必须补救）
  if gap >= 1 → 🟡 中等缺口（建议提升）
  if gap <= 0 → 🟢 匹配或超出
```

    "Python": {"self": 8, "required": 8, "gap": 0, "status": "✅ 匹配"},
    "向量数据库": {"self": 8, "required": 7, "gap": -1, "status": "✅ 超出"},

## 三、定向 Mock 题生成

### 生成规则

根据 Gap 分析的结果，Skill **动态调整题库**：

| Gap 状态 | Mock 题策略 |
|---|---|
| 🔴 严重缺口（gap ≥ 3） | 生成**基础补课题**（帮候选人快速补到及格线）+ 准备**被问到时的应对话术** |
| 🟡 中等缺口（gap 1-2） | 生成**深挖题**（验证是否真的不够，还是自评保守） |
| 🟢 超出/匹配 | 生成**压力测试题**（你自评高，面试官会加倍质疑） |
| JD 加分项但自评低 | 生成**"诚实说不知道"的应对话术**（面试中承认 + 展示学习意愿） |

### 定向 Mock 题示例

#### 场景：JD 要求系统设计 7 分，候选人自评 5 分

**Mock 题 1（基础补课）**：
> "设计一个 AI 客服系统，支持 1 万并发。画出你的架构图。"

**Mock 题 2（追问压力测试）**：
> "你说用了消息队列削峰，那如果队列积压了 10 万条消息，消费者挂了，你怎么处理？"
> "你的限流策略是什么？按用户？按接口？按模型？"
> "如果主模型服务挂了，你有降级方案吗？降级到什么？"

**应对话术（如果真的不会）**：
> "这个我目前经验不够深，我之前做的是小规模系统（<100 并发）。
> 但我有思考过扩展方案：用消息队列做异步化、用 Redis 做限流、用多副本做高可用。
> 最近在读《Designing Data-Intensive Applications》和 vLLM 的架构文档，
> 也在自己搭一个压测环境来实验。如果入职后需要负责这部分，我可以在 1-2 个月内补齐。"

#### 场景：JD 加分项"推理优化"，候选人自评 2 分

**Mock 题**：
> "你们线上推理用什么框架？知道 vLLM 的 PagedAttention 吗？"

**应对话术**：
> "坦白说这块是我的短板，我目前主要用 API 调用和简单的模型部署。
> 我知道 vLLM 的 PagedAttention 是借鉴了操作系统的虚拟内存分页思想，
> 把 KV Cache 分块管理来减少显存碎片。
> 这是我接下来重点学习的方向，已经在看 vLLM 的源码和论文。"

## 四、面试前的 Gap 预警

Skill 在面试开始前，向候选人展示：

```
⚠️ 基于你的简历 + 目标 JD 分析，以下是你的高危缺口：

🔴 系统设计（JD 要求 7，你自评 5）
   → 面试中大概率被问到，建议：
   → 今晚画 3 张架构图（RAG系统 / Agent系统 / 模型服务）
   → 每个图想清楚：入口、限流、降级、监控

🔴 推理优化（JD 加分，你自评 2）
   → 面试官可能试探，准备好"诚实+学习意愿"的话术
   → 不要硬编，会被追问穿帮

🟡 模型微调（JD 要求 5，你自评 4）
   → 把 LoRA 原理再复习一遍，确保能手推
   → 准备一个"我想学但还没机会"的真实理由

✅ RAG（你 9 分，JD 要求 8）
   → 这是你的王牌，面试官会重点挖
   → 确保第三层（踩坑+量化）能流畅说出
```

## 五、面试后的 Gap 更新

每轮面试结束后：

1. Skill 根据候选人的**实际回答**，更新自评矩阵中的分数
2. 重新计算 Gap
3. 在报告中展示"自评 vs 实际表现"的差异

```
你的自评 vs 面试实测：

| 技能 | 自评 | 实测 | 差异 |
|---|---|---|---|
| RAG | 9 | 8 | -1（自评略高，第三层有卡壳） |
| Agent | 7 | 7 | 0（准确） |
| 系统设计 | 5 | 3 | -2（自评偏高，被压力题打回原形） |
| Python | 8 | 8 | 0（准确） |

结论：你的"系统设计"实际水平比自评低 2 分，
这是接下来最需要补的方向。
```

## 六、多 JD 对比

如果候选人投了多家公司，Skill 支持同时分析多个 JD：

```
你的简历 vs 各公司 JD 匹配度：

| 公司 | 岗位 | 匹配度 | 你的核心优势 | 你的关键缺口 |
|---|---|---|---|---|
| 字节 | AI应用开发 | 72% | RAG经验丰富 | 系统设计、高并发 |
| 阿里 | Agent工程师 | 81% | Agent实战经验 | 多Agent编排深度 |
| 腾讯 | 大模型后端 | 65% | Python编码强 | 推理优化、C++ |
| 创业公司A | 全栈AI | 88% | 技术广度好 | 产品思维 |

建议面试顺序：创业公司A（练手）→ 阿里（主战场）→ 字节（压力测试）→ 腾讯（最后）
```

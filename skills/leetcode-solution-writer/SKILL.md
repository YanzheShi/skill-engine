# LeetCode 题解生成助手

用于配合 VSCode LeetCode 插件，在 `~/.leetcode/docs/` 目录下创建题解文档。

## 核心工作流程

### 第一步：识别题目

从以下来源确定题号和题目标题：
1. 从会话参数$ARGUMENTS里面获取（如 `生成第<problem-id>题的题解`，`生成<problem-slug>题目的题解`）
2. 从对话上下文里面获取 （如会话上下文里面有第<problem-id>题或者<problem-slug>）
3. **当前打开的题目文件**（如 `49.字母异位词分组.cpp`）
4. 从文件头部注释解析题号：`@lc app=leetcode.cn id=49`
5. 从文件名提取题号：正则匹配 `(\d+)\.`

### 第二步：获取题目信息

使用 `scripts/fetch_problem.py` 获取题目数据：

```bash
# 从文件解析
python scripts/fetch_problem.py --file /path/to/problem.cpp

# 直接指定题号
python scripts/fetch_problem.py 49
```

脚本直接调用 LeetCode GraphQL API 获取题目数据，无需外部依赖。

### 第三步：创建题解目录和文件

在 `~/.leetcode/docs/` 下创建目录结构：
```
{题号}. {题目标题}/
└── 题解.md
```

例如：
```
49. 字母异位词分组/
└── 题解.md
```

### 第四步：基于模板填充结构

**重要**：使用 `assets/solution-template.md` 作为模板，**严格按照模板的 markdown 结构**生成题解。

模板结构（必须遵守）：
```markdown
# 思路X：{思路名称}

## 解题思路
**核心思想**：{一句话概括}

**算法流程**：
1. {步骤一}
2. {步骤二}
3. {步骤三}

## 复杂度
- 时间复杂度：{分析}
- 空间复杂度：{分析}

## Code
```cpp
{代码实现}
```

**问题/优化方向**：{如果有}

---

# 总结对比
| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
...
```

**格式要求**：
- 思路标题：`#`（一级标题）
- 子节标题：`##`（二级标题）
- 必须包含：`## 解题思路`、`## 复杂度`、`## Code` 三个二级标题
- **不要**使用其他格式（如 `**核心思想**` 作为独立段落）

### 第五步：从对话历史提取真实思考过程

**最关键**：不要只写成功的解法，必须记录**完整的思考历程**，包括失败的尝试。

#### 5.1 提取思路演进顺序

从对话历史中按时间顺序提取所有思路，包括：

1. **最自然的想法**（往往是暴力法）
   - 用户的原话："最自然的想法是..."
   - 标记为"思路一"

2. **失败的优化尝试**（如果有）
   - 用户尝试过但失败的方法
   - 记录为什么失败
   - 标记为"思路X（❌ 失败尝试）"
   - 示例：
     ```
     **尝试过程**：
     1. 想到用哈希表优化暴力法中的重复计算问题
     2. 尝试了**字符求和法**：
        ```cpp
        int hash(string str) {
            int hash_val = 0;
            for (char ch : str) {
                hash_val += (int)ch;
            }
            return hash_val;
        }
        ```
     3. 发现问题：会有**哈希碰撞**
        - "ac" = 97 + 99 = 196
        - "bb" = 98 + 98 = 196
        - 不是字母异位词的词被分到了一组！

     **问题/优化方向**：
     - 找不到一个完美的哈希函数...
     - **卡了 6-7 分钟**，一度认为面试要完蛋了
     - **关键突破**：在面试官的引导下发现...
     ```

3. **成功的解法**（最终通过的方法）
   - 记录关键的"恍然大悟"时刻
   - 标记为"思路X"或"思路X（✅ 推荐解法）"

4. **进一步优化**（如果有讨论）

从对话历史中提取：

   - "我简单的分析了一下..."

#### 5.4 提取关键词与核心洞察

**最重要**：这是题解的精华部分，用于快速复习时抓住本质。

**从对话历史中提取**：

1. **关键词**（3-5个）

   - 重要的编程模式（如"原地修改"、"哨兵节点"）
   - **不只是列出关键词，要说明学到了什么**
   - 示例：
     ```
     - **滑动窗口**：不只是"避免临时数组的额外空间"，更深层次的原因是"能够快速跳过不可能的子数组"

     ```

2. **本题 Insight**
   - 对算法本质的深度理解，超越表面的实现细节
   - 记录"恍然大悟"时刻：对某个概念的认知升级
   - 示例：
     ```
     - **双指针法的本质**：不只是"省空间"，而是"快速排除不可能的解"
     - **动态规划的本质**：不是"记忆化搜索"，而是"从小问题递推到大问题"
     ```

3. **易错点**
   - 实现中容易出错的细节
   - 边界情况的处理
   - 示例：
     ```

     - 循环结束后要再检查一次当前窗口长度（最长子串在末尾的情况）

for (string& s : strs) {

## 示例：好的题解 vs 不好的题解

### ✅ 好的题解（有情景感，记录完整历程）

```markdown
# 思路一：暴力法

## 解题思路

**核心思想**：对每个字符串，遍历数组找到它的所有字母异位词，组成一组。

这是我最自然的想法：对于每个词，找到它的字母异位词，然后放入结果临时数组中，然后删除选中的词。

**算法流程**：
1. 外层循环遍历每个字符串 `s`
2. 内层循环遍历所有未被分组的字符串 `t`
3. 判断 `s` 和 `t` 是否是字母异位词
4. 将异位词加入当前分组，标记已处理

## 复杂度
- 时间复杂度：O(n² × k)
- 空间复杂度：O(n)

## Code
```cpp
// ... 代码 ...
```

**问题/优化方向**：
存在大量重复比较，时间复杂度过高。每次判断两个字符串是否为字母异位词时，都要重新计算字符计数，造成重复计算。

---

# 思路二：自定义哈希函数（❌ 失败尝试）

## 解题思路

**核心思想**：设计一个哈希函数，让字母异位词映射到同一个整数。

我简单的分析了一下，选中某个词的其它异位词的方法可以使用链哈希表优化。我们构造一个哈希函数 `hash(str)`，相同的词具有相同的字母组成。

**尝试过程**：
1. 想到用哈希表优化暴力法中的重复计算问题
2. 尝试了**字符求和法**
3. 发现问题：会有**哈希碰撞**
   - "ac" = 97 + 99 = 196
   - "bb" = 98 + 98 = 196
   - 不是字母异位词的词被分到了一组！

## Code
```cpp
// 尝试但失败的代码
int hash(string str) {
    int hash_val = 0;
    for (char ch : str) {
        hash_val += (int)ch;
    }
    return hash_val;
}
// 问题："ac" 和 "bb" 的哈希值相同，但它们不是字母异位词
```

**问题/优化方向**：
- 找不到一个完美的哈希函数
- **卡了 6-7 分钟**，一度认为面试要完蛋了（"15分钟写完我想个思路想个6、7分钟不完蛋了"）
- **关键突破**：在面试官的引导下发现，不应该执着于"自定义哈希函数"，而应该**转换数据表示**

---

# 思路三：哈希表 + 排序

## 解题思路

**核心思想**：将每个字符串排序后作为哈希表的 key。

这是在面试官引导下发现的方法：
- 面试官问："字母异位词有什么共同特点？"

- 面试官问："如果我想让 'eat'、'tea'、'ate' 变成同一个字符串，应该怎么处理？"
- 我恍然大悟："排序！"
```

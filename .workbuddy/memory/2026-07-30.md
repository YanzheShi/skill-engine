# 2026-07-30 工作日志

## Windows 路径空转（WinError 267）根因修复

用户原命令 `skill-engine session -s code-builder -w /d/Code/PycharmProjects/demo-project`（Git Bash 风格 `/d/...`）在 Windows 原生 Python 上每条 bash 命令都抛 `[WinError 267] 目录名称无效`，异常被 `format_observation` 吞成 `exit_code: -1`，模型无诊断信息只能空转到迭代上限。

**根因**：`Executor._run` 用 `subprocess.run(..., cwd=...)` 执行命令，`cwd` 来自用户传入的 `-w /d/...`（POSIX 写法）。Windows 原生 Python 把 `/d/x` 当非法目录直接抛 `WinError 267`；异常被吞成 `-1`，LLM 看不出根因。

**四层修复**（已落码 + 测试通过）：
1. 新建 `src/skill_engine/execution/paths.py`：`posix_to_windows`/`to_native_path`/`native_path_hint` 把 `/d/x`、`/mnt/d/x`、`/cygdrive/d/x` 转 `D:\x`，展开 `~`；Windows 上才转，Linux/macOS 原样。
2. `executor.py`：`_run` 执行前 `to_native_path(cwd)` 校验 `is_dir()`，无效返回结构化可读 stderr（含 `D:` 纠正写法），不再抛被吞的 `WinError`。
3. `tool_dispatch.py`：`working_root`/`_resolve_path` 归一化；`build_env_header` 在 `final_prompt` 前注入 `<env>` 块（OS/shell/工作目录/路径风格，点名禁止 `/mnt/d/`）；`format_observation` 调 `_diagnose_shell_error` 在已知失败时补可执行 hint，打断空转。
4. `runner.py` + `cli.py`：`run_repl` 与 `run`/`session` 命令对 `working_root` 归一化，无效目录**快速失败**（CLI 直接 `[ERROR] 工作目录不存在` 退出 exit=1），不空跑 30 轮。

**验证**：`tests/test_windows_paths.py` 30 passed；原有 `test_repl_session.py`(17) / `test_tool_pluggable.py`(7) / `test_context_manager.py`(8) 无回归。端到端：原 `-w /d/...` 命令打印 `[INFO] 工作目录已归一化为原生路径: D:\Code\PycharmProjects\demo-project` 后正常进会话；无效目录立刻退出。

**原则**：在 Windows 上执行引擎默认走 Windows 原生目录（`D:\...`），用户仍可传 `/d/...` 等写法，由 `paths.py` 自动归一化。
